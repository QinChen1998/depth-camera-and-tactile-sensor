# 深度图 SDK 首版工作清单

首版目标是让当前 Windows x64 上位机通过 SDK 实现三种深度方案、共享原视频、设备接入、启停重连和普通深度保存。以 2026-11-12 工作区的产品入口和帧契约为基线。建议采用一套 SDK，通过设备 ID、成像方案和推理后端选项完成配置。[产品入口](../DCTS_APP.json) · [项目架构](ARCHITECTURE.md)

Windows 首版的构建、公开接口和独立示例见 [Windows x64 深度图 SDK](DEPTH_SDK_WINDOWS.md)。

## 多设备支持

| 对象 | 当前实现 | 首版做法 |
| --- | --- | --- |
| 多块 RV1103 | 设备库保存多份受信任档案和一个当前设备 ID。主窗口创建一个会话，深度图和原视频共用。切换档案时停止当前会话。 | 用同一 SDK 枚举档案、按设备 ID 打开、停止后切换。首版每个调用进程运行一个采集会话。会话持有选定档案的快照，深度与视频订阅同一会话。 |
| 多块板同时插 USB | 一键连接发现多个 ADB 候选时会报告歧义。现有 USB 网络设置使用固定地址，依赖对应的 RNDIS 网卡和路由。 | 首版保留单板 USB 一键连接的行为，向上位机返回歧义错误，解除歧义后按设备身份继续接入。 |
| 三种成像方案 | 上位机辅助推理和板端推理使用 mode24。板端推理高精度使用 mode25。三个方案共享 RV1103 采集链路和默认 F6 标定。 | 在同一会话接口上选择方案，按设备能力和配套文件的校验结果开放档位。 |
| 多种主机推理设备 | 同一主机模型支持 TensorRT-RTX、DirectML、OpenVINO GPU／CPU 和 ONNX Runtime CPU。混合 INT8 由用户手动选择。 | 统一枚举、选择和报告实际后端。按后端组织模型和运行库，继续用子进程隔离现有运行时。 |

当前深度产品以 RV1103 和配套采集协议为设备范围。拆成多套 SDK 会重复维护档案、USB 登记、标定、启停和上位机接入。未来新增协议不同的深度相机时，可以在同一接口下增加设备实现和能力声明。磁触觉设备继续由上位机的串口模块管理。[设备档案](../sensors/RvDeviceStore.h) · [会话绑定](../SensorMainWindow.cpp) · [USB 发现](../sensors/RvUsbEnrollment.cpp) · [推理设备](MULTI_BACKEND_INFERENCE.md)

## 开发清单

先用独立示例跑通已登记设备的普通板端深度和原视频，再接入高精度档与主机推理。补齐 USB 流程后进行上位机整体验收。

- [x] **定义公开接口和生命周期。** 建议采用带版本的 C ABI，交付头文件、Windows DLL 和导入库。使用不透明会话句柄、固定宽度数据类型及结构体大小字段。公开设备枚举与能力查询、按 ID 打开／关闭、选择成像方案、开始／停止／立即重连、查询状态及订阅帧和事件。定义启动、切换、恢复、断流、停止及错误的状态语义，明确停止请求、本地停止完成及板端所有权状态。约定回调线程、帧缓冲区的持有／释放方式、队列上限及关闭时的回调边界。

- [x] **从上位机入口抽出可独立运行的会话。** 复用 `RvSessionController`、视频与 ToF 接收、`RvControlWorker` 和主机推理链路。SDK 初始化显式接收运行资源和设备库位置。界面偏好、翻译和回调转发到 UI 线程由上位机适配层负责。内部可继续使用 Qt，公开接口使用普通 C/C++ 数据类型，明确内部事件循环的初始化和退出方式。当前 `DctsInferenceWorker.exe` 由主程序复制生成，候选探测也会重新启动上位机 EXE。将探测、测速和推理迁到 SDK 可定位的独立 worker。[共享会话](../sensors/RvSessionController.h) · [构建定义](../Depth%20Camera%20and%20Tactile%20Sensor.vcxproj) · [推理候选探测](../sensors/RvInferenceSettings.cpp) · [运行资源定位](../RuntimeDiscovery.cpp)

- [x] **接入设备管理和 USB 登记。** 沿用现有档案、SSH 身份校验和 Windows 凭据引用，兼容已有档案的编辑、默认设备和导入导出。提供 USB 发现与只读检查、确认后执行登记或修复所需的操作和进度。上位机处理确认提示和自动启动策略。SDK 复核同一 USB transport、序列号、公钥和 boot ID，保留 F6 标定、整套板端载荷校验、长期参数和失败回滚。切换设备或用户停止后，使过期的检查、导入后自动启动和帧事件失效。[设备管理](../sensors/RvDeviceManagerDialog.cpp) · [USB 登记](../sensors/RvUsbEnrollment.cpp) · [默认标定](DEFAULT_CALIBRATION_NATIVE_TOF.md)

- [x] **接入推理后端。** 提供候选枚举、选择、实际后端及失败状态和手动测速入口。上位机从现有偏好恢复选择，SDK 负责兼容性检查和运行时回退。保持启动轻量检测和 INT8 手动选择。模型身份、密文认证或依赖完整性校验失败时报告错误，保持现有受保护运行包的加载约束。[多后端行为](MULTI_BACKEND_INFERENCE.md) · [模型保护](MODEL_PROTECTION.md)

- [x] **定义帧与快照接口。** 帧明确携带设备、会话和采集代次、来源帧号、时间戳及其时钟域、宽高、行跨度、格式和标定标识。订阅原视频解码帧用于共享视频页。深度快照返回同次发布的米制数组、元数据及可用的配对图像。数组按行存放小端 float32，剩余无效位置记为 0。下表尺寸按宽 × 高书写。[原生帧](../sensors/RvTofFrame.h) · [主机输出](ARCHITECTURE.md#主机深度数据链路) · [快照格式](../sensors/DepthSnapshot.h)

  | 成像方案 | 深度数值与配套信息 |
  | --- | --- |
  | 上位机辅助推理 | 480×640 的 camera-Z 深度。提供同次输出的配对 RGB、校正点、有效性和侧区补显所需的预测与掩码。按 RGB 选择软件时间预算内最新合格 ToF，200 ms 总预算含 35 ms 时钟裕量。保留 ToF 复用、沿用历史倍率和单目估计的状态。 |
  | 板端推理／板端推理高精度 | 48×32 的原生径向距离，按原生网格顺序交付。标识有效测距、缺测和补点估计。原视频独立订阅。 |

- [x] **让现有上位机切到 SDK。** 深度图与原视频页通过同一个 Qt 适配层消费状态和帧。保持三档菜单及旧设置迁移、自动启动／停止／重连、切换进度、色标、悬停和旋转。按档案执行模型输入方向与输出逆恢复，显示旋转由视图处理。原有普通快照保存浮点深度、色彩图和元数据，上位机辅助档按选项保存同帧配对 RGB。侧区补显只用于预览，保存和悬停仍取数值深度。恢复期间旧画面可短时保留，等待新帧时保持保存禁用。[深度图](../sensors/DepthMapWidget.cpp) · [原视频](../sensors/RtspCameraPage.cpp) · [深度视图](../sensors/RvDepthView.cpp)

- [x] **构建并验证 Windows SDK 包。** 提供最小接入示例和接口说明。随包准备所需的 worker、标定与板端导入载荷、视频依赖和推理运行时，校验版本及 SHA256。对接现有安装版的加密模型加载。客户交付时核对指定交付目录的第三方许可和模型使用声明。[构建与验证](TESTING.md) · [许可记录](OPEN_SOURCE_LICENSES.md)

## 首版验收

- [x] 在 Windows x64 上使用独立运行包和系统 PATH，从 C 示例打开受信任设备，验证原视频、三档深度、停止与重连。受保护模型随包运行。
- [x] Release 和 Debug 分别通过现有八组离线专项。与接入前 worker 做同模型、同后端及同输入对照，12 份有效深度输出逐字节一致。上位机离线回归覆盖普通保存和侧区补显。
- [x] 单块 RV1103 实机通过 USB 只读检查、已登记设备复用和断流恢复。恢复在同一 boot 使用新的采集代次。板端首次部署、修复和回滚通过离线夹具验证。双档案切换和多个 USB 候选的歧义处理通过离线验证。[现有测试入口](TESTING.md) · [板端采集](../tools/rv_capture/README.md)
- [ ] 两块实板依次连接切换的验证。当前实机验证使用一块 RV1103。
