# 默认标定与原生 ToF 模式

2026-11-09：以 `RV1103_Camera_ToF_Calibration_Technical_Report_20261109.pdf` 及同目录发布文件为依据，所有新连接统一使用 `rv20261109-f6`，设备管理不再提供标定下拉框。已有设备档案载入时迁移至该默认值；本轮先清空此前保存的设备，再登记本次完成验证的设备。

## 三个成像档位

| 深度图选项 | 采集模式 | 传感器模式 | 深度数组 |
|---|---|---|---|
| 上位机辅助推理 | 14 | `-d 5`，16×16 普通 | RGB672 模型输出 640×480 camera-Z 米制深度，H 矫正 |
| 板端推理 | 24 | `-d 11`，48×32 普通 | 48×32 原生径向距离，米，float32 |
| 板端推理高精度 | 25 | `-d 12`，48×32 高精度 | 48×32 原生径向距离，米，float32 |

两档“板端推理”名称按用户要求显示，实际输出直接来自 ToF。距离由原生 UQ2 值乘 0.00025 转为米，无效测点为 0；不进行网络推理、插值或相机坐标变换。显示采用最近邻放大，原始索引与保存数组保持一致。原生深度没有与视频严格配对，因此不提供配对视频保存。

两档原生 ToF 默认额外顺时针旋转 90°显示。深度图顶部的“输入角度”按钮接受 0–359°，两档共用并保存到 `depth/nativeTofRotationDegrees`。该按钮仅在原生档位显示；角度叠加于原视频底栏已有的全局画面旋转。两档原生画面在全部旋转完成后，按屏幕左右方向水平镜像一次；UniDepth 和摄像头显示保持原有处理。任意角度的画布完整适配视口，悬停通过旋转及镜像的逆变换返回原始测点索引与距离；原始米制数组与保存图像保持原始网格，保存元数据记录显示角度及 `native_tof_display_mirror_horizontal=true`。此调整只改变画面方向，不是新的几何标定。

设备管理不再提供“摄像头安装角度”控件，仍保留“上位机推理输入朝向”。编辑并保存已有设备时保留原档案的旧安装角度字段，避免改变历史输入方向配置；此项界面移除不改动模型预处理、标定或视频旋转。

三个档位共用采集和视频会话。选择档位会停止旧 generation，再应用新预设，接收实际网格匹配的新数据后完成切换。均为单目标、Signal/Noise 关闭；周期、积分和 SNR 沿用板端保存值，预设不写长期参数。过期深度撤销数值，停止后不接受迟到结果。

## 默认标定与自动导入

发布文件保存在 `assets/camera/calibration_20261109/`。`tools/calibration/import_release.py` 按已固定 SHA256 导入 calibration、intrinsics、extrinsics、projection、GEO2 和 manifest，并生成 H 所需的 RGB672 校正映射及 `host_contract.json`。ONNX 原模型保持不变，虚拟输入网格和模型裁剪保持不变。

物理相机参数用于未旋转、未镜像、未校正的 2304×1296 原帧；输入映射只应用一次 Brown 校正。Native48 的 F6 射线及 Native16 射线经一次轴变换与同一组 R/t 投影。每次采集自动选择 F6 软件射线表，并验证同 generation 的标定回执；传感器真实 FOV 仍独立记录，不写 EEPROM。模型输入方向与输出逆恢复仍成对处理；显示旋转独立。F1/F2 历史几何仅用于已有 H 诊断回放。

USB 一键连接、自动连接文件检查和“安装板端采集支持”共用完整文件计划。导入内容包括纯采集程序、SPI 驱动、相机与服务脚本、工程调参运行文件、完整标定包，以及 `tools/rv_capture/payload/dtof-host.sh` 的三个档位切换内容。切换内容嵌入部署的 `session.sh`，不依赖额外安装步骤。每个文件核对 SHA256，已有文件全部一致时直接复用。

USB 检测同时要求 ADB 身份与该序列号对应的 Windows USB 网卡在线。未连接、网卡尚未枚举或检测中途拔出时，后台静默等待，不弹“导入失败”；手动连接仍提供失败诊断。板端探测会短暂等待固件将启动临时地址切换到 `172.32.0.93/16`，复核身份时允许正常的地址变化。手动连接遇到旧固件的其他地址时，为已核验身份的 `usb0` 补充受管地址与启动脚本，保留其他地址；同一地址前缀修复失败时恢复原值。受管启动文件更新保留 `.previous` 原件。不会修改其他 Windows 网卡或仅凭网卡名称选择目标。

`tools/rv_control/build.ps1` 在 Release/Debug 运行目录各生成 `board-import.json`，列出全部板端载荷的哈希、固定 F6 和模式 14/24/25。新的 SPI 驱动支持自动 F6 选择，替换旧驱动仅接受 F1/F2 的限制。这个完整闭包同时用于未安装的新设备、已有匹配设备和旧版本/文件损坏的设备；无需从当前板上复制文件给下一台设备。

活动标定位于板端 `/root/r144_depth/calibration_current/`，几何位于 `/root/r144_depth/M48_geometry.bin`。事务式安装保留原长期参数与回滚目录；完成验证后，本轮按用户要求清理旧目录中的退役模型和专用程序。主机保留 H 运行包，板端不部署模型或 RKNN 依赖。

## 验证入口

本轮证据目录为 `x64/validation/calibration_default_20261109/`。离线测试涵盖发布哈希、全部射线、投影与映射、三档参数、48×32 数据帧和故障拒绝、设备迁移、部署回滚、UI 与启停；使用 `tools/run_offline_tests.py` 执行 Release/Debug 专项。实机入口为 `--usb-enrollment-live-validation` 和 `--imaging-switch-validation`；后者验证 H→普通→高精度→H→高精度→普通→H，并逐字节比较原生深度与同帧测量转换。

实机验证报告记录实际结果。通信、切换和数值一致性通过不等于重新测定物理精度；本轮没有重新采集标定数据，也没有制作安装包。

本轮已完成的结果汇总在 [verification.json](../x64/validation/calibration_default_20261109/verification.json)：Release/Debug 各八组、1360 项离线检查全部通过；最终显示变更又通过各四组相关回归。Python 48 项、SPI 射线选择与回执 1803 项 C 断言、两个控制 worker 各 59 项检查通过；H 模型 22 个同输入案例通过，13 个有输出的案例在 Release/Debug 间逐字节一致。

当前设备通过完整覆盖导入、重复连接不重写文件、七次 H/普通/高精度往返切换。两档原生数组均与同帧 UQ2 换算结果逐字节一致，H 配对不超过 100 ms，停止后迟到深度为 0。旧设备记录删除 2 条，随后只登记当前验证设备。主机清理 7 个旧源码/载荷文件；板端删除 12 个退役模型、程序、NPU 库及实验入口文件，保留参数、几何和采集回滚材料。

追加 30 帧原生统计：普通模式每帧 352–377 个非零距离，高精度 34–48 个；这是当时场景的输出，不能解释成精度优劣。传感器有效位也可能对应零距离，显示保持黑色，不伪造补点。完整导入包同时覆盖新板初始化与旧板更新；首次阶段未以另一台实物板作验收，空白固件路径由隔离安装测试覆盖。后续在另一台带旧 F1 交付的新接入设备上，完成完整替换、重复连接、H 深度绘制与七次三档切换；结果见 `x64/validation/usb_startup_20261109/verification.json`。Release/Debug 各 294 项相关回归、16 项隔离 USB 网络脚本测试通过。
