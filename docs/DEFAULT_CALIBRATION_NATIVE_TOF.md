# 默认标定与原生 ToF 模式

2026-11-09：以 `RV1103_Camera_ToF_Calibration_Technical_Report_20261109.pdf` 及同目录发布文件为依据，所有新连接统一使用 `rv20261109-f6`，设备管理不再提供标定下拉框。已有设备档案载入时迁移至该默认值；本轮先清空此前保存的设备，再登记本次完成验证的设备。

## 成像档位

| 深度图选项 | 采集模式 | 传感器模式 | 深度数组 |
|---|---|---|---|
| 上位机辅助推理（G） | 24 | `-d 11`，48×32 普通 | 480×640 竖幅 camera-Z 米制深度，每份 ToF 更新一次尺度 |
| 上位机辅助推理（B，复用 ToF） | 24 | `-d 11`，48×32 普通 | 同一竖幅网格，允许复用最新合格 ToF |
| 板端推理 | 24 | `-d 11`，48×32 普通 | 48×32 原生径向距离，米，float32 |
| 板端推理（1200K） | 24 | `-d 11`，48×32 普通，主积分 1200K | 48×32 原生径向距离，米，float32 |
| 板端推理高精度 | 25 | `-d 12`，48×32 高精度 | 48×32 原生径向距离，米，float32 |
| 板端推理高精度（1200K） | 25 | `-d 12`，48×32 高精度，主积分 1200K | 48×32 原生径向距离，米，float32 |

板端原生档直接显示 ToF 测量。距离由原生 UQ2 值乘 0.00025 转为米，无效测点为 0。显示采用最近邻放大，原始索引与保存数组保持一致。原生深度没有与视频严格配对，因此不提供配对视频保存。

各原生档默认额外顺时针旋转 90°显示。深度图顶部的“输入角度”按钮接受 0–359°，各档共用并保存到 `depth/nativeTofRotationDegrees`。该按钮仅在原生档位显示，角度叠加于原视频底栏的全局画面旋转。板端画面在全部旋转完成后，按屏幕左右方向水平镜像一次。任意角度的画布完整适配视口，悬停通过逆变换返回原始测点索引与距离。保存使用原始网格，元数据记录显示角度及 `native_tof_display_mirror_horizontal=true`。

设备管理不再提供“摄像头安装角度”控件，仍保留“上位机推理输入朝向”。编辑并保存已有设备时保留原档案的旧安装角度字段，避免改变历史输入方向配置；此项界面移除不改动模型预处理、标定或视频旋转。

成像档位共用采集和视频会话。G 和 B 在会话有效时共用 mode24，切换先清空主机配对和尺度历史。其他档位切换后，收到匹配的新数据即完成。预设使用单目标并关闭 Signal 和 Noise。普通和高精度 1200K 档仅覆盖本次会话的主积分，周期和 SNR 沿用板端保存值。传感器读回 1200K 后才开始出图，连续测量的 `session.json` 记录具体档位、模式号及实读参数。切回原普通或高精度档即使用板端保存的积分。过期或停止后撤销深度。

## 默认标定与自动导入

发布文件保存在 `assets/camera/calibration_20261109/`。`tools/calibration/import_release.py` 按已固定 SHA256 导入 calibration、intrinsics、extrinsics、projection、GEO2 和 manifest，并生成 RGB672 校正映射及 `host_contract.json`。主机沿用原模型，在模型输出恢复标定方向后裁取竖幅。

物理相机参数用于未旋转、未镜像、未校正的 2304×1296 原帧；输入映射只应用一次 Brown 校正。Native48 的 F6 射线及 Native16 射线经一次轴变换与同一组 R/t 投影。每次采集自动选择 F6 软件射线表，并验证同 generation 的标定回执；传感器真实 FOV 仍独立记录，不写 EEPROM。模型输入方向与输出逆恢复仍成对处理；显示旋转独立。F1/F2 历史几何仅用于已有 H 诊断回放。

USB 一键连接、自动连接文件检查和“安装板端采集支持”共用完整文件计划。导入内容包括纯采集程序、SPI 驱动、相机与服务脚本、工程调参运行文件、完整标定包，以及 `tools/rv_capture/payload/dtof-host.sh` 的会话预设。预设嵌入部署的 `session.sh`。每个文件核对 SHA256，已有文件全部一致时直接复用。

USB 检测同时要求 ADB 身份与该序列号对应的 Windows USB 网卡在线。未连接、网卡尚未枚举或检测中途拔出时，后台静默等待，不弹“导入失败”；手动连接仍提供失败诊断。板端探测会短暂等待固件将启动临时地址切换到 `172.32.0.93/16`，复核身份时允许正常的地址变化。手动连接遇到旧固件的其他地址时，为已核验身份的 `usb0` 补充受管地址与启动脚本，保留其他地址；同一地址前缀修复失败时恢复原值。受管启动文件更新保留 `.previous` 原件。不会修改其他 Windows 网卡或仅凭网卡名称选择目标。

`tools/rv_control/build.ps1` 在 Release/Debug 运行目录各生成 `board-import.json`，列出全部板端载荷的哈希、固定 F6 和模式 14/24/25。新的 SPI 驱动支持自动 F6 选择，替换旧驱动仅接受 F1/F2 的限制。这个完整闭包同时用于未安装的新设备、已有匹配设备和旧版本/文件损坏的设备；无需从当前板上复制文件给下一台设备。

活动标定位于板端 `/root/r144_depth/calibration_current/`，几何位于 `/root/r144_depth/M48_geometry.bin`。事务式安装保留长期参数与回滚目录。UniDepth 运行包部署在主机，板端部署纯采集程序。

设备空闲时，可在「设置 → 设备管理 → 维护板端文件」按当前上位机的部署清单核对文件及 SHA256。检查范围是 `/root/r144_depth`、`/root/dtof_candidates_20261009` 和 `/root/dtof_tuner` 三个采集目录，保留调参持久化目录与相机配置备份。发现缺失、变更或多余文件时，用完整载荷事务式更新并读回校验。较旧的已完成回滚和本次替换出的运行文件先归档到主机 `%LOCALAPPDATA%\DctsBoardArchives\rv1103`，核对归档 SHA256 后移除板端副本。板端至多保留一份既有回滚。当前文件符合清单时复用现有运行目录。

## 验证入口

使用 `tools/run_offline_tests.py` 验证 F6 射线、投影、配对、48×32 数据、设备迁移、界面和启停。`--usb-enrollment-live-validation` 覆盖实机接入。`--imaging-switch-validation` 覆盖 G、普通、高精度和两个 1200K 档之间的往返切换，核对 1200K 档的主积分回读，并逐字节比较原生深度与同帧测量转换。通过测量对话框录制和验证 1200K 原始帧的入口见[测量采集专项](TESTING.md)。

## 2026-11-09 历史结果

实机验证报告记录实际结果。通信、切换和数值一致性通过不等于重新测定物理精度；本轮没有重新采集标定数据，也没有制作安装包。

本轮已完成的结果汇总在 [verification.json](../x64/validation/calibration_default_20261109/verification.json)：Release/Debug 各八组、1360 项离线检查全部通过；最终显示变更又通过各四组相关回归。Python 48 项、SPI 射线选择与回执 1803 项 C 断言、两个控制 worker 各 59 项检查通过；H 模型 22 个同输入案例通过，13 个有输出的案例在 Release/Debug 间逐字节一致。

当前设备通过完整覆盖导入、重复连接不重写文件、七次 H/普通/高精度往返切换。两档原生数组均与同帧 UQ2 换算结果逐字节一致，H 配对不超过 100 ms，停止后迟到深度为 0。旧设备记录删除 2 条，随后只登记当前验证设备。主机清理 7 个旧源码/载荷文件；板端删除 12 个退役模型、程序、NPU 库及实验入口文件，保留参数、几何和采集回滚材料。

追加 30 帧原生统计：普通模式每帧 352–377 个非零距离，高精度 34–48 个；这是当时场景的输出，不能解释成精度优劣。传感器有效位也可能对应零距离，显示保持黑色，不伪造补点。完整导入包同时覆盖新板初始化与旧板更新；首次阶段未以另一台实物板作验收，空白固件路径由隔离安装测试覆盖。后续在另一台带旧 F1 交付的新接入设备上，完成完整替换、重复连接、H 深度绘制与七次三档切换；结果见 `x64/validation/usb_startup_20261109/verification.json`。Release/Debug 各 294 项相关回归、16 项隔离 USB 网络脚本测试通过。
