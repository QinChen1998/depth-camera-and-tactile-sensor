# 默认标定与原生 ToF 模式

2026-11-09：以 `RV1103_Camera_ToF_Calibration_Technical_Report_20261109.pdf` 及同目录发布文件为依据，所有新连接统一使用 `rv20261109-f6`，设备管理不再提供标定下拉框。已有设备档案载入时迁移至该默认值；本轮先清空此前保存的设备，再登记本次完成验证的设备。

## 成像档位

| 深度图选项 | 采集模式 | 传感器模式 | 深度数组 |
|---|---|---|---|
| 上位机辅助推理 | 24 | `-d 11`，48×32 普通 | RGB 选时间预算内最新的合格 ToF，允许用同一测量对多张 RGB 分别拟合。输出 480×640 camera-Z 米制深度 |
| 板端推理 | 24 | `-d 11`，48×32 普通 | 48×32 原生径向距离，米，float32 |
| 板端推理高精度 | 25 | `-d 12`，48×32 高精度 | 48×32 原生径向距离，米，float32 |

两档“板端推理”输出 ToF 径向距离。距离由原生 UQ2 值乘 0.00025 转为米，缺测点输出为 0 或板端补点估计值。显示采用最近邻放大，原始索引与保存数组保持一致。原生深度与视频独立采集，因此不提供配对视频保存。

### 板端深度补点

RV1103 在原生网格上处理单格缺测。5×5 窗口其余 24 格均为有效测距时，用全部邻点拟合局部深度斜面。至少 22 格须落在残差容差内，其余残差也有上限。若多对相邻点在同一行或列边界出现同方向的深度阶跃，则保留缺测。

5×5 外圈也有缺测时，中心周围 8 格必须全部有效且支持同一表面。在前一原始帧的同位置和八邻位置比较 5×5 邻域的有效分布与深度。只有最佳匹配明确，且对齐后的前帧中心和八邻格都支持同一表面，才使用本帧拟合值。连续缺口和开放轮廓保留无效。跨会话、跳帧、告警及帧间隔超过 220 ms 时跳过历史检查。

内部孤点的基础残差容差按径向距离取普通档 3%（15–35 mm）、高精度档 2%（10–26 mm）。靠轮廓的本帧残差容差分别取 1%（12–30 mm）和 0.8%（8–24 mm）。阈值按 0.25 mm 量化。普通档使用历史原始帧回放验证，高精度档使用合成帧验证。实际轮廓误补率和板端处理耗时仍需按场景测量。

两档板端显示在 LSG2 请求中显式启用 `native48-hole-fill-v1`。估计值作为同帧独立载荷返回，原始测距、SNR 与有效位仍供原始帧消费者读取。上位机辅助推理只请求原始 ToF。板端深度的悬停读数标注估计点，保存元数据的 `native_hole_fill_indices` 列出补点在原始 48×32 数组中的索引。

两档原生 ToF 默认额外顺时针旋转 90°显示。深度图顶部的“输入角度”按钮接受 0–359°，两档共用并保存到 `depth/nativeTofRotationDegrees`。该按钮仅在原生档位显示；角度叠加于原视频底栏已有的全局画面旋转。两档原生画面在全部旋转完成后，按屏幕左右方向水平镜像一次；UniDepth 和摄像头显示保持原有处理。任意角度的画布完整适配视口，悬停通过旋转及镜像的逆变换返回原始测点索引与距离；原始米制数组与保存图像保持原始网格，保存元数据记录显示角度及 `native_tof_display_mirror_horizontal=true`。此调整只改变画面方向，不是新的几何标定。

设备管理不再提供“摄像头安装角度”控件，仍保留“上位机推理输入朝向”。编辑并保存已有设备时保留原档案的旧安装角度字段，避免改变历史输入方向配置；此项界面移除不改动模型预处理、标定或视频旋转。

三项共用采集和视频会话。切换时应用相应预设，并在收到符合实际网格的数据后完成切换。各档均为单目标，关闭 Signal 和 Noise。周期、积分和 SNR 沿用板端保存值。过期深度撤销数值，停止后拒绝迟到结果。

## 默认标定与自动导入

发布文件保存在 `assets/camera/calibration_20261109/`。`tools/calibration/import_release.py` 按已固定 SHA256 导入 calibration、intrinsics、extrinsics、projection、GEO2 和 manifest，并生成上位机推理所需的 RGB672 校正映射及 `host_contract.json`。ONNX 原模型保持不变，虚拟输入网格和模型裁剪保持不变。

物理相机参数用于未旋转、未镜像、未校正的 2304×1296 原帧；输入映射只应用一次 Brown 校正。Native48 的 F6 射线及 Native16 射线经一次轴变换与同一组 R/t 投影。每次采集自动选择 F6 软件射线表，并验证同 generation 的标定回执；传感器真实 FOV 仍独立记录，不写 EEPROM。模型输入方向与输出逆恢复仍成对处理；显示旋转独立。

USB 一键连接、自动连接文件检查和「安装板端采集支持」共用同一文件计划。导入纯采集程序、SPI 驱动、会话预设、内参、外参、射线几何、相机 ISP 配置脚本及工程调参。逐项核对 SHA256，完全匹配时复用。修复保留可读取的长期参数并验证新会话生成的私有相机配置。

登记时若上位机仍在检测推理设备，检测结束后复核设备档案、USB 连接、板端启动身份和停止操作，再继续启动。断流后，板端须报告恢复能力，并出具原会话正常退出和释放资源的回执。身份变化、采集仍被占用、故障锁和传感器读回故障会拒绝恢复，并返回具体原因。

USB 检测同时要求 ADB 身份与该序列号对应的 Windows USB 网卡在线。未连接、网卡尚未枚举或检测中途拔出时，后台静默等待，不弹“导入失败”；手动连接仍提供失败诊断。板端探测会短暂等待固件将启动临时地址切换到 `172.32.0.93/16`，复核身份时允许正常的地址变化。手动连接遇到旧固件的其他地址时，为已核验身份的 `usb0` 补充受管地址与启动脚本，保留其他地址；同一地址前缀修复失败时恢复原值。受管启动文件更新保留 `.previous` 原件。不会修改其他 Windows 网卡或仅凭网卡名称选择目标。

`tools/rv_control/build.ps1` 在 Release/Debug 运行目录各生成 `board-import.json`，列出全部板端载荷的哈希、固定 F6、模式 14/24/25 和 48×32 补点能力。USB 首次导入和已有设备修复共用该载荷，激活前校验新程序的哈希、标定和补点协议。旧程序的摘要不同，会进入原有的确认及事务式替换流程。新的 SPI 驱动支持自动 F6 选择，替换旧驱动仅接受 F1/F2 的限制。

活动标定位于板端 `/root/r144_depth/calibration_current/`，几何位于 `/root/r144_depth/M48_geometry.bin`。事务式安装保留原长期参数与回滚目录。UniDepth 模型由主机运行包提供。

## 验证入口

离线入口为 `tools/run_offline_tests.py`。实机入口为 `--usb-enrollment-live-validation` 和 `--imaging-switch-validation`。切换专项从上位机辅助推理出发，先按普通档、高精度档的顺序往返，再反向往返，并核对原生深度与同帧测量转换。

以下为 2026-11-09 标定导入及当时 H 与原生 ToF 的历史验证记录。

实机验证报告记录实际结果。通信、切换和数值一致性通过不等于重新测定物理精度；本轮没有重新采集标定数据，也没有制作安装包。

本轮已完成的结果汇总在 [verification.json](../x64/validation/calibration_default_20261109/verification.json)：Release/Debug 各八组、1360 项离线检查全部通过；最终显示变更又通过各四组相关回归。Python 48 项、SPI 射线选择与回执 1803 项 C 断言、两个控制 worker 各 59 项检查通过；H 模型 22 个同输入案例通过，13 个有输出的案例在 Release/Debug 间逐字节一致。

当前设备通过完整覆盖导入、重复连接不重写文件、七次 H/普通/高精度往返切换。两档原生数组均与同帧 UQ2 换算结果逐字节一致，H 配对不超过 100 ms，停止后迟到深度为 0。旧设备记录删除 2 条，随后只登记当前验证设备。主机清理 7 个旧源码/载荷文件；板端删除 12 个退役模型、程序、NPU 库及实验入口文件，保留参数、几何和采集回滚材料。

追加 30 帧原生统计：普通模式每帧 352–377 个非零距离，高精度 34–48 个；这是当时场景的输出，不能解释成精度优劣。传感器有效位也可能对应零距离，显示保持黑色，不伪造补点。完整导入包同时覆盖新板初始化与旧板更新；首次阶段未以另一台实物板作验收，空白固件路径由隔离安装测试覆盖。后续在另一台带旧 F1 交付的新接入设备上，完成完整替换、重复连接、H 深度绘制与七次三档切换；结果见 `x64/validation/usb_startup_20261109/verification.json`。Release/Debug 各 294 项相关回归、16 项隔离 USB 网络脚本测试通过。
