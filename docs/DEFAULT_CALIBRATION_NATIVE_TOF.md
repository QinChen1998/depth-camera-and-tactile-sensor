# 默认标定与原生 ToF 模式

所有新连接统一使用 `rv20261109-f6`。该标定对应 `RV1103_Camera_ToF_Calibration_Technical_Report_20261109.pdf` 及同批发布文件。已有设备档案载入时迁移至固定默认标定。设备管理提供主机推理输入朝向设置。

## 成像档位

| 深度图选项 | 采集模式 | 传感器模式 | 深度数组 |
|---|---|---|---|
| 上位机辅助推理 | 24 | `-d 11`，48×32 普通 | Depth Pro 2-S 480×640 竖幅 camera-Z，复用最新合格 ToF |
| 板端推理 | 24 | `-d 11`，48×32 普通 | 48×32 原生径向距离，米，float32 |
| 板端推理高精度 | 25 | `-d 12`，48×32 高精度 | 48×32 原生径向距离，米，float32 |

板端档在 48×32 原生索引上显示 ToF 径向深度。原生 UQ2 值乘 0.00025 转为米，LSG2 补洞估计可填补符合条件的无效点，估计索引保存在深度快照元数据中。点云、测量采集和上位机 ToF 校正使用原生测点。显示采用最近邻放大，原生档的快照只保存深度及元数据。

各原生档默认额外顺时针旋转 90°显示。深度图顶部的“输入角度”按钮接受 0–359°，各档共用并保存到 `depth/nativeTofRotationDegrees`。该按钮仅在原生档位显示，角度叠加于原视频底栏的全局画面旋转。板端画面在全部旋转完成后，按屏幕左右方向水平镜像一次。任意角度的画布完整适配视口，悬停通过逆变换返回原始测点索引与距离。保存使用原始网格，元数据记录显示角度及 `native_tof_display_mirror_horizontal=true`。

设备管理不再提供“摄像头安装角度”控件，仍保留“上位机推理输入朝向”。编辑并保存已有设备时保留原档案的旧安装角度字段，避免改变历史输入方向配置；此项界面移除不改动模型预处理、标定或视频旋转。

成像档位共用采集和视频会话。上位机辅助推理与普通档均使用 mode24，切换清除旧显示结果。SDK 的两个板端档默认主积分为 1200K，并沿用工程调参保存的自定义参数。测量报告在收到传感器回读时记录主积分。过期或停止后清除深度。

## 默认标定与自动导入

发布文件保存在 `assets/camera/calibration_20261109/`。`tools/calibration/import_release.py` 按已固定 SHA256 导入 calibration、intrinsics、extrinsics、projection、GEO2 和 manifest，并生成 RGB672 校正映射及 `host_contract.json`。主机取校正后的 360×480 ToF 重叠区域并等比采样到 480×640，再送入 Depth Pro 2-S。输出恢复到同一标定网格。

物理相机参数用于未旋转、未镜像、未校正的 2304×1296 原帧；输入映射只应用一次 Brown 校正。Native48 的 F6 射线及 Native16 射线经一次轴变换与同一组 R/t 投影。每次采集自动选择 F6 软件射线表，并验证同 generation 的标定回执；传感器真实 FOV 仍独立记录，不写 EEPROM。模型输入方向与输出逆恢复仍成对处理；显示旋转独立。F1/F2 历史几何仅用于已有 H 诊断回放。

上位机通过 CXWL Depth Camera SDK 2.2.2 的 C ABI 枚举 USB 设备、检查身份与配套文件，并在需要时登记、修复或恢复设备。已登记设备的检查通过后，应用复用该设备开始成像。需要配置 USB 网络或写入配套文件时，用户可在「设置 → 设备管理」使用「USB 一键连接」。

工程控制 worker 的构建入口 `tools/rv_control/build.ps1` 生成 `board-import.json`，列出配套采集载荷的 SHA-256、固定 F6 和模式 14/24/25。安装构建校验这份清单及载荷摘要后收集采集和调参支持。

活动标定位于板端 `/root/r144_depth/calibration_current/`，几何位于 `/root/r144_depth/M48_geometry.bin`。设备修复保留长期参数和回滚材料。Depth Pro 2-S 运行包部署在主机，板端使用原生采集程序。

设备空闲时，可在「设置 → 设备管理 → 检查板端文件」发起检查。SDK 按需修复采集运行文件，并将旧回滚副本归档到主机。当前文件通过检查时复用现有运行目录。

## 验证入口

使用 `tools/run_offline_tests.py` 验证 F6 射线、投影、配对、48×32 数据、设备迁移、界面和启停。`--usb-enrollment-live-validation` 覆盖实机接入。`--imaging-switch-validation` 覆盖上位机辅助、普通板端和高精度板端三档往返切换，核对主积分回读和同帧米制深度。1200K 原始帧的测量采集命令见 [实机专项](TESTING.md#实机专项)。

## 2026-11-09 历史结果

实机验证报告记录实际结果。通信、切换和数值一致性通过不等于重新测定物理精度；本轮没有重新采集标定数据，也没有制作安装包。

当轮 Release/Debug 各八组、1360 项离线检查全部通过，最终显示变更又通过各四组相关回归。Python 48 项、SPI 射线选择与回执 1803 项 C 断言、两个控制 worker 各 59 项检查通过。H 模型 22 个同输入案例通过，13 个有输出的案例在 Release/Debug 间逐字节一致。汇总原路径为 `x64/validation/calibration_default_20261109/verification.json`，可从 本地归档索引 `archives/README.md` 查询。

当时的验证设备通过完整覆盖导入、重复连接不重写文件、七次 H/普通/高精度往返切换。两档原生数组均与同帧 UQ2 换算结果逐字节一致，H 配对不超过 100 ms，停止后迟到深度为 0。旧设备记录删除 2 条，随后登记本轮验证设备。主机清理 7 个旧源码/载荷文件，板端删除 12 个退役模型、程序、NPU 库及实验入口文件，保留参数、几何和采集回滚材料。

追加 30 帧原生统计：普通模式每帧 352–377 个非零距离，高精度 34–48 个；这是当时场景的输出，不能解释成精度优劣。传感器有效位也可能对应零距离，显示保持黑色，不伪造补点。完整导入包同时覆盖新板初始化与旧板更新；首次阶段未以另一台实物板作验收，空白固件路径由隔离安装测试覆盖。后续在另一台带旧 F1 交付的新接入设备上，完成完整替换、重复连接、H 深度绘制与七次三档切换；结果见 `x64/validation/usb_startup_20261109/verification.json`。Release/Debug 各 294 项相关回归、16 项隔离 USB 网络脚本测试通过。
