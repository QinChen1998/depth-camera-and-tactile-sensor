# 触想工作台

触想工作台是独立的 Windows x64 传感器上位机，由 `Dexterous Hand Visualization` 移植。主窗口提供磁触觉、深度图、原视频和点云。

- 磁触觉传感器：串口采集、三维力显示、曲线和显示设置。
- 深度图提供 **上位机辅助推理**、**板端推理**和**板端推理高精度**。上位机方案使用 Depth Pro 2-S 和复用 ToF 的 B 策略，两个板端档显示 SDK 的 48×32 米制径向深度及有效测点。
- 摄像头原视频与深度共用 CXWL Depth Camera SDK 2.2.2 的成像会话，视频为 2304×1296 H.265。
- 点云可从「视图 → 点云」或「深度图」旁的标签页打开。480×640 上位机辅助深度和 48×32 原生 ToF 均支持点状与网格，按相机 Z 共用 Jet 色标。默认「固定 Z 色标」使用 0.01–3 m，可在点云下方调整范围。切换到「动态＋直方图均衡」后，颜色按单帧深度分布映射。上位机辅助点径默认 2.4 px。点状与网格使用当前帧。左键拖动旋转，中键拖动平移，滚轮手动缩放。帧刷新和切档时保留视角，点击「重置视角」可恢复默认。
主窗口由成像方案自动选择 dToF 模式。工程调参使用专项工具。默认标定和 USB 接入见 [默认标定与原生 ToF 模式](docs/DEFAULT_CALIBRATION_NATIVE_TOF.md)。

## 上位机辅助推理

主机从 2304×1296 视频按 F6 校正表取中心的 360×480 ToF 重叠区域，再等比采样为 480×640 输入 Depth Pro 2-S。TensorRT 引擎直接输出同网格的米制相机 Z。输入朝向设为 180° 时，worker 在推理后逆旋转输出。RGB、ToF 投影、点云和保存使用同一组竖幅内参。

上位机复用最新的合格 ToF 测量，配对时间差与时钟裕量合计最多 200 ms。无合格配对时，当前会话可沿用最近可靠尺度。点击「仅显示单目深度」可同时查看深度图和点云在 ToF 校正前的同帧结果。普通保存使用校正后的米制深度。

「显示 ToF 测点」标记同帧原生测点，白圈表示参与校正的点。「ToF / RGB 对照」在配对 RGB 上显示测点。「录制诊断（10秒）」保存配对 RGB、原生 ToF、单目预测、筛点原因及最终深度。

## 测量采集

打开「文件 → 测量采集」，选择 **RV1103** 或 **Gemini 335**，设置 30–60 秒及保存目录。可选填实测距离和场景备注。RV1103 沿用深度图选定的成像档位，录制页可启动已登记的会话。Gemini 335 使用 Windows 已安装的 Orbbec SDK v2，以 1280×800、15 FPS 录制原生深度。

每组生成独立目录。`session.json` 记录采集状态、格式、实测距离、总帧数和序号间隙，`frames.jsonl` 记录每帧的字节偏移、长度、帧号、源时间和主机接收时间。`depth.bin` 按索引连存原生数据。RV1103 板端档的每个测区依次为小端 UQ2 距离、SNR、有效位，并随组保存 F6 `geometry.bin`。主机辅助档保存有对应内参的 float32 米制相机 Z。Gemini 335 保存小端 Y16 距离码，换算毫米时乘该组的 `scale_mm_per_code`，零为无效。

48 × 32 原生档的已测指标、平板和阶差件参考尺寸及取数方法见[深度性能规格](docs/RV1103_TMF8829_48x32_深度性能规格.md)。

## 运行

开发版双击根目录的 **`START_RELEASE.cmd`**。安装版从「触想工作台」快捷方式启动。主机 FP16 推理需要兼容的 NVIDIA GPU、驱动及本地 Depth Pro 2-S 运行包。缺少有效运行包或推理初始化失败时，程序使用普通板端档。此前明确选择的板端档位仍可恢复。

### 磁触觉

普通启动在磁触觉模块首次可见后尝试一次默认串口，优先使用上次成功的参数。首次连接默认选择首个可用端口、921600 波特率、地址 1 和 F 模块。收到有效测量后自动设置一次显示 delta 零点，正常约 0.5–0.9 秒。到期仍无稳定均值时，使用本次连接最新的有效帧。置零期间以 10 ms 请求后间隔采样，结束后恢复用户设置。

「连接设置」启动时展开，「显示设置」启动时收起，之后由用户手动显隐。默认请求后间隔及下限为 10 ms，从一笔请求完成后计时。界面独立以约 30 Hz 刷新。数据不可用时保留模型，数值显示「--」。

磁触觉自动、手动和热插拔连接均先读取实际型号，再将采集及界面切到对应的指尖 F、末端 G 或超薄 S 模块。同一波特率下，当前地址读取失败时尝试厂家公共地址 0，并读取实际 ID、复核型号后继续采集。公共地址恢复用于单传感器总线。识别失败时提示用户检查波特率或从站 ID；用户可手动打开“连接设置”修改并重新连接，成功时自动纠正所选型号。每次连接使用当前波特率。

磁触觉“显示方式”按实际输出点数选择：指尖/末端触觉为 20、65、136 点，超薄触觉为 16、49、100 点。首次启动默认选择 136 点档（切换超薄触觉时为 100 点）和流畅渲染，后续恢复用户选择。模型、曲线和列表使用同一档点数；列表可选择任意输出点查看曲线。新增点沿用现有表面插值，原始采集与历史仍保留 20/16 个测点。三维数据约每 33 ms 更新，列表和曲线各自合并更新，置零、点选和显示设置即时刷新。模型上的固定 P 编号不再显示，点位、箭头和相机操作保持原有方式。

列表仅显示零点差值，表头为 X、Y、Z；未设置有效零点或数据不可用时显示“--”。delta 仍由当前值减去原始零点基线计算。硬件“抑制轻微读数”只作用于模型、曲线和列表的 X、Y 分量，绝对值不超过设置阈值时归零；关闭后恢复完整差值。Z 分量始终正常显示，不受抑制开关和噪声阈值影响。

“显示通信状态”每次启动时关闭，关闭时不占用布局空间。打开后可查看串口、设备地址、接收计数和错误信息，有过滤错误原因时才显示对应提示。重置视角和正面视角位于设置 delta 零点右侧。模拟数据生成、场景选择和底部模拟控件已移除；串口采集通过连接设置中的“断开”停止。

### RV1103 设备管理

使用 USB 数据线连接 RV1103，从「设置 → 设备管理」点击「USB 一键连接」。SDK 检查 ADB、RNDIS、设备身份和板端文件，按需登记设备或更新配套采集服务。已登记且配套文件匹配的设备可以自动开始当前成像方案。深度图、点云和原视频共用采集会话。

设备列表可以切换或移除登记设备，并检查板端文件、恢复设备和检查矫正网格。主机推理的 0°／180° 输入方向可在列表下方调整。重标双绿矫正网格时，停止采集，将 SC3336 对准均匀照明的哑光白面。点击「检查矫正网格」，核对状态后确认计算。SDK 采集 21 帧 Bayer RAW，计算本机 Gr／Gb 的 17×17 网格，经 ISP 试加载和读回后更新设备。

板端普通和高精度分别请求 SDK 的普通与高精度模式。SDK 2.2.2 的两档默认主积分为 1200K，旧版出厂 600K 参数由 SDK 升级流程迁移。SDK 继续尊重工程调参保存的自定义参数。测量报告在获得传感器实读值时记录该值。

上位机使用 SDK 的视频解码时间和 ToF 回传时延估计在同一主机时钟配对。配对时间差与时钟裕量合计上限仍为 200 ms。诊断保留所用的时间来源、同代次 ToF 质量图、筛点原因和最终米制深度。

## 独立配置

`config/` 保存本软件自己的设备档案和 INI 偏好。首次启动从随程序编译的 `config/first-run-settings.ini` 初始化磁触觉、深度图及原视频的可移植设置，后续使用本地保存的用户偏好。模板不包含 COM 口、设备地址、身份、标定或凭据。视频流地址由当前受信任设备档案生成。两软件后续各自保存；日常运行不会读写原软件的配置。本应用的窗口布局单独保存，不导入含机械手等模块的旧窗口布局。Windows 凭据仍由系统管理。

`DepthPro2Runtime/` 存放本机引擎、worker、CUDA 与 TensorRT 用户态运行库及许可。以 `tools/depthpro2/build.ps1` 组装匹配的运行包。

## 开发

VS 2022 v143，Windows SDK 10.0.22621.0，Qt 6.11.1 MSVC x64，QtMsBuild。直接打开根目录同名 `.sln` 并选择 x64 配置即可构建。工程用系统自带的 Windows PowerShell 校验 `CXWLDepthSDK-2.2.2-win64.zip` 的 SHA-256、解包并部署所需文件。其他开发机可用 `DCTS_DEPTH_SDK_ZIP` 指定该 ZIP 的路径。也可运行下面的命令。

```powershell
./tools/build_desktop.ps1 -Configuration Release -QtRoot E:/Qt/6.11.1/msvc2022_64
./tools/build_desktop.ps1 -Configuration Debug -QtRoot E:/Qt/6.11.1/msvc2022_64
```

构建默认同时重建配套的原生 RV worker 并更新其依赖 SHA-256 清单。产物位于 `x64/<配置>/触想工作台.exe`。当前 Windows SDK 和 Visual Studio 构建验证见 [SDK 同步记录](SDK_SYNC_CHECKLIST.md)。

离线专项统一使用 `tools/run_offline_tests.py`，涵盖 UI、触觉、调参、恢复及 USB 登记八组。脚本隔离配置和临时目录，缺报告、零断言或 FAIL 均判失败。新版模型专项检查 480×640 张量、0°／180°输入、同帧输出与 B 策略。详细命令与有效代码行数口径见 [测试与源码统计](docs/TESTING.md)。

维护进度见 [精简清单](REFACTOR_CHECKLIST.md)，已执行的第 1–7 类清理见 [第二轮记录](docs/SOURCE_CLEANUP_PHASE2.md)，原始候选与第一轮结果见 [第一轮记录](docs/SOURCE_CLEANUP_REVIEW.md)。构建、filters、RCC、文档和 CAD 来源路径可用 `tools/audit_source.py` 核对。纯采集构建入口见 [板端源码与构建](tools/rv_capture/README.md)，CAD 与历史产物见 归档索引 `archives/README.md`。工程中间输出统一放在 `x64/`，原始模型和用户配置保持。

## 安装包

当前安装包包含 SDK、原生采集支持、界面及视频运行库。安装器和 SHA-256 文件生成在构建目录的 `delivery/`。本地研究所用的 Depth Pro 2-S 运行包单独组装。构建与沙盒验证见 [安装包构建](docs/MODEL_PROTECTION.md#当前安装包)。

## 历史验证

早期移植工具及结果在 2026-11-08 ZIP 的 `x64/validation/port_import/` 和 `x64/validation/verification.json`。当时两个配置各通过 7 组专项和 28 个原生合成场景，其中各有 19 份有效输出逐字节一致。同一 ZIP 内的 `x64/validation/live_5min/gui_two_modes_300s.json` 记录了 F2 实机两轮约 300 秒测试，板端 LiteSR 实际绘制 4.72 FPS，FP16＋16×16 H 实际绘制 29.97 FPS。历史报告的查询和恢复方法见 本地归档索引 `archives/README.md`。
