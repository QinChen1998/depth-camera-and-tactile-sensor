# 触想工作台

由 `Dexterous Hand Visualization` 的当前工作副本移植的独立上位机。保留原模块界面和数据链路，精简主窗口，只提供：

- 磁触觉传感器：串口采集、三维力显示、曲线和显示设置。
- 深度图：**上位机辅助推理**使用宽视野 RGB576 FP16＋16×16 ToF，仅方案 H；**板端推理**使用板端 LiteSR 近距离完整模型＋上位机轮廓＋高清视频 H.265。
- 摄像头原视频：与深度图共用一个 RV1103 会话，原 2304×1296 H.265 链路；128×128 板端模式关闭相机。

新增 **板端推理（128×128，相机关闭）**：16×16 原生深度＋同帧光子强度，8 倍输出。沿用既有 LiteSR 权重，未重训；模型从独立副本生成 AES-256-GCM 加密包，原 256×256 和 384×256 方案保留。

不包含机械手模型、关节控制、手势、人手跟随、手套、其他深度模型包，也不提供独立原生 dToF/光子计数模块。主窗口由成像方案自动选择 dToF 模式，无手动调参入口。调参源码保留供工程专项验证。深度菜单、设备管理、渲染、语言、浮动/停靠、布局恢复和布局预设均保留。

工作区的 `START_RELEASE.cmd` 和 Visual Studio 的 Release/Debug 默认使用 ONNX Runtime 1.31.1 和 TensorRT-RTX EP，加载本地明文 UniDepthV2-Small RGB576 FP16 模型。安装版使用同一模型和执行后端，通过原生 DLL 认证并解密 AES-256-GCM 模型后在内存中创建会话。

工作区可在深度图的「成像方案」选择「上位机辅助推理（640×480）」。该档位从原视频校正取样 672×504 RGB，由 UniDepth FP16 模型中心裁出 640×480 米制深度，并在这个网格上进行 H 矫正。其运行包位于 `UniDepthRuntimeRgb672VgaFP16RTX/`，需要 TensorRT-RTX。

新增实验入口「板端推理（384×256）」：原生 48×32 深度和光子计数输入，工作网格 96×64，输出 384×256。复用原权重，保持原生径向米与传感器视场；原「板端推理」256×256 和主机方案仍可选择。模型导入会核验并安装两个独立加密包。具体合同、限制和验证入口见 [矩形 LiteSR 接入](docs/LITESR384_INTEGRATION.md)。本轮不生成安装包。

## 运行

双击根目录 **`START_RELEASE.cmd`**。已在本项目内配齐 Qt 6.11.1 MSVC x64 运行库；主机 FP16 推理另需兼容 NVIDIA GPU/驱动。普通启动在磁触觉模块首次可见后尝试一次默认串口：优先使用上次成功的端口、波特率、设备地址和模块，没有记录时使用首个可用端口、921600、地址 1 和 F 模块。收到首份 CRC 正确且量程有效的数据后，短暂等待稳定并以连续有效帧均值自动设置一次显示 delta 零点，成功后显示完成状态。正常通信时从首份有效测量起约 0.5～0.9 秒完成；置零期间临时按 10 ms 请求后间隔采样，随后立即恢复用户设置，因此 100 ms 甚至 60000 ms 的常规间隔也不会拉长置零等待。等待期间保留模型，暂不显示力箭头及曲线；到 0.9 秒仍未得到稳定均值时，自动用本次连接的最新有效帧设置一次 delta 零点，正常显示完成状态，不再提示手动置零。“连接设置”每次启动默认展开，“显示设置”默认收起；之后仅由用户通过设置按钮或卡片内的最小化按钮显隐。连接成功、置零、连接失败、断开、热插拔重连和模块启停均不改变两个面板的显隐，展开状态不跨启动恢复。默认请求后间隔及下限为 10 ms，采集中可直接调整；该间隔从上次请求完成后计时，另加串口传输和设备响应耗时，界面按独立的约 30 Hz 刷新。轻微读数抑制默认开启，已有显示偏好继续保留。未连接设备、数据失效或切换到未连接型号时，保留模型并显示“设备未连接/数据不可用”，列表显示“--”，不会生成模拟读数。

磁触觉自动、手动和热插拔连接均先读取实际型号，再将采集及界面切到对应的指尖 F、末端 G 或超薄 S 模块。同一波特率下，当前地址读取失败时尝试厂家公共地址 0，并读取实际 ID、复核型号后继续采集。公共地址恢复用于单传感器总线。识别失败时提示用户检查波特率或从站 ID；用户可手动打开“连接设置”修改并重新连接，成功时自动纠正所选型号。每次连接使用当前波特率。

上位机启动后检测当前受信任设备。设备已连接且板端推理模型、dToF 自动切换文件均通过校验时，按当前成像方案自动开始。设备稍后连接也会触发检查。深度图和摄像头原视频的「开始」「停止」「立即重连」控制同一个采集会话。用户停止后，同一次连接保持停止。离线专项和 `RV_TEST_OFFLINE_ONLY=1` 跳过默认串口、设备检测和自动成像，不开启硬件。delta 置零仅改变本次会话的显示基线，不写入传感器或修改原始读数。

### RV1103 USB 首次连接

首次启动的设备列表为空。启动时已插入及运行中插入的未登记 RV1103 均通过与「USB 一键连接」相同的流程触发添加提示，确认后可为尚无 IPv4 地址的交付板配置 USB 网络。使用 USB 数据线，板端需启用 ADB 和 RNDIS，使用下述 V1.2.0 交付板或已部署兼容深度服务和 GEO2 标定的设备。Windows 需识别两个 USB 功能。将 Android SDK Platform-Tools 的 `adb.exe` 及随附 DLL 放在主程序旁的 `platform-tools/`；直接运行 EXE 时也可使用 PATH 中的 ADB。

弹窗显示序列号、SSH 指纹和根据几何文件核对的 F1/F2 标定。核对摄像头安装角度和上位机推理输入朝向后，点击「添加设备」。两项默认均为 0°。上位机复用兼容地址，或将无 IPv4 的板端 `usb0` 配置为 `172.32.0.93/16` 并设置开机恢复；Windows 端仅配置对应的 USB 网卡为 `172.32.0.100/16`，可能出现系统管理员权限提示。登录采用预置的 `root` / `luckfox`。SSH 公钥、序列号和标定验证通过后，密码保存至 Windows 凭据管理器，设备加入设备管理、设为当前默认设备并按当前成像模式启动。取消后，可保持 USB 连接，在「设置 → 设备管理」点击「USB 一键连接」，重新确认并添加设备。

V1.2.0 RGB＋SPI ToF 交付板首次连接时，上位机核对原交付驱动、板端身份及固件依赖。确认使用匹配 F1 标定的相机与 ToF 安装后，自动部署原生采集服务、高清视频配置、F1 标定、加密 LiteSR 及会话切换支持。首次设置会接管原厂相机启动，保留原厂启动脚本备份，保留交付驱动备份并安装精确接受有效 `0x11` 的配套驱动，继续使用板载相机程序。SPI 节点缺失时，仅对已识别的 Luckfox 配置工具应用交付使用的临时 SPI0 配置。板端校验通过后登记设备并按当前成像方案启动。 一键连接或板端文件安装失败时，弹窗会显示诊断报告路径并提供「打开所在文件夹」，便于用户将报告交给运维。

磁触觉“显示方式”按实际输出点数选择：指尖/末端触觉为 20、65、136 点，超薄触觉为 16、49、100 点。首次启动默认选择 136 点档（切换超薄触觉时为 100 点）和流畅渲染，后续恢复用户选择。模型、曲线和列表使用同一档点数；列表可选择任意输出点查看曲线。新增点沿用现有表面插值，原始采集与历史仍保留 20/16 个测点。三维数据约每 33 ms 更新，列表和曲线各自合并更新，置零、点选和显示设置即时刷新。模型上的固定 P 编号不再显示，点位、箭头和相机操作保持原有方式。

列表仅显示零点差值，表头为 X、Y、Z；未设置有效零点或数据不可用时显示“--”。delta 仍由当前值减去原始零点基线计算。硬件“抑制轻微读数”只作用于模型、曲线和列表的 X、Y 分量，绝对值不超过设置阈值时归零；关闭后恢复完整差值。Z 分量始终正常显示，不受抑制开关和噪声阈值影响。

“显示通信状态”每次启动时关闭，关闭时不占用布局空间。打开后可查看串口、设备地址、接收计数和错误信息，有过滤错误原因时才显示对应提示。重置视角和正面视角位于设置 delta 零点右侧。模拟数据生成、场景选择和底部模拟控件已移除；串口采集通过连接设置中的“断开”停止。

开始、采集中切换和可恢复的重连均由共享成像会话选择对应预设。空闲时选择方案会在下次开始时应用。

| 成像方案 | dToF 会话参数 | 相机 |
|---|---|---|
| 板端 128×128 | 16×16 普通、33 ms、单目标、Signal 开、Noise 关 | 关闭 |
| 板端 256×256／384×256 | 48×32 普通、原保存周期、单目标、Signal 开、Noise 关 | 恢复 H.265 |
| 主机 RGB576／640×480 H | 16×16 普通、原保存周期、单目标、Signal 和 Noise 关 | 恢复 H.265 |

SPI 时钟、积分参数和标定沿用板端原配置；仅 128×128 会话将周期覆盖为 33 ms，不改长期参数。H 沿用 100 ms 最新测量配对、复用及历史尺度规则。128×128 不使用 RGB 或主机轮廓补洞，保留原生索引、径向米制深度和有效掩码。

首次添加和「验证连接」会检查加密 LiteSR 与 dToF 自动切换支持。设备空闲时，点击「设置 → 设备管理 → 安装板端推理与自动切换」，即可使用随软件提供的文件完成安装，无需选择模型。手动「开始」发现缺少可补装文件时，可按提示安装并继续启动。程序按设备标定选择 F1/F2 运行程序，在板端校验密文并从内存初始化 RKNN 后启用。原脚本按 SHA-256 备份，普通升级保留已有明文模型。该单独安装入口适用于已部署兼容深度服务的设备。V1.2.0 交付板的首次完整安装从「USB 一键连接」进入。

会话预设在停止或断电后失效。导入的脚本和模型保存在板端文件系统。当前 RV1103 的开机脚本只启动状态服务，等待上位机开始采集。其他镜像若在开机时自行启动深度服务，沿用该镜像原有的持久参数。上位机开始成像时会重新应用所选方案的预设。

## 独立配置

`config/` 保存本软件自己的设备档案和 INI 偏好。首次启动从随程序编译的 `config/first-run-settings.ini` 初始化磁触觉、深度图及原视频的可移植设置，后续使用本地保存的用户偏好。模板不包含 COM 口、设备地址、身份、标定或凭据。视频流地址由当前受信任设备档案生成。两软件后续各自保存；日常运行不会读写原软件的配置。本应用的窗口布局单独保存，不导入含机械手等模块的旧窗口布局。Windows 凭据仍由系统管理。

`UniDepthRuntimeWide576FP16RTX/` 提供日常 TensorRT-RTX 模型、DLL 和许可材料。`UniDepthRuntimeWide576FP16/` 保留原始明文模型和 CUDA EP 运行包，用于安装包构建和历史对照。两者都在本项目内独立运行。

## 开发

VS 2022 v143，Windows SDK 10.0.22621.0，Qt 6.11.1 MSVC x64，QtMsBuild。打开根目录同名 `.sln`，或运行：

```powershell
./tools/build_desktop.ps1 -Configuration Release -QtRoot E:/Qt/6.11.1/msvc2022_64
./tools/build_desktop.ps1 -Configuration Debug -QtRoot E:/Qt/6.11.1/msvc2022_64
```

构建默认同时重建配套的原生 RV worker 并更新其依赖 SHA256 清单，产物位于 `x64/<配置>/触想工作台.exe`。首次移植的一次性工具与文件指纹仅保存在 `x64/validation/port_import/`，不属于日常构建。

需要复现 CUDA 对照时，可为单独的开发构建显式传入 `/p:DctsUseCudaEp=true`。

离线专项入口包括 `--port-ui-smoke-test`、`--tactile-3d-test`、`--tactile-render-test`、`--tactile-serial-test`、`--tactile-visualization-test`、`--rv-assist-recovery-test`、`--rv-tuner-test`，随后传绝对报告路径。这些入口使用隔离配置，不连接真实设备。历史 CUDA 逐字节对照可用 `tools/verify_port.py` 对原软件和显式 CUDA 构建运行相同的合成 H 输入，验证模型清单、0°/180°还原、F1/F2、100 ms 复用边界、逐字节输出、停止重启及不同输入。

数值一致性与离线通过不等于实景精度或 FPS 验收。日常运行不需要 Python。验证证据保存在忽略的 `x64/validation/`；不自动提交或推送。

离线验证结果见 `x64/validation/verification.json`：两配置各 7 组专项、各 28 个原生合成场景、本地运行库启动与正常退出通过；每配置 19 份有效深度/诊断结果与原软件逐字节一致。这些离线专项不启动真实摄像头或串口采集。

用户随后明确授权在 `172.32.0.93`（F2）实机测试并在两模式之间保存/恢复传感器配置。真实主窗口中两模式各运行约 300 秒：板端 LiteSR 实际绘制 1,415 帧、平均 4.72 FPS；FP16＋16×16 H 接收 8,993 份深度、实际绘制 8,991 帧、平均 29.97 FPS，含 4,499 份明确标记的 dToF 复用结果。两模式高清视频均约 30 FPS，停止后晚到深度为 0。最后设备空闲，原 48×32 参数及两份长期配置文件 SHA256 完全恢复。未保存真实图像或测量数组。详见 `x64/validation/live_5min/gui_two_modes_300s.json`。

历史实机验证工具 `tools/run_live_validation.py` 使用当时的长期参数保存流程复现上述基线。自动切换版本应在导入板端脚本后，通过真实主窗口验证两模式往返及停止，无需预先保存 16×16 参数。
