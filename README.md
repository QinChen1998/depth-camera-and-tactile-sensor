# 触想工作台

由 `Dexterous Hand Visualization` 的当前工作副本移植的独立上位机。保留原模块界面和数据链路，精简主窗口，只提供：

- 磁触觉传感器：串口采集、三维力显示、曲线和显示设置。
- 深度图提供 **上位机辅助推理**、**板端推理**和 **板端推理高精度**。上位机输出 480×640 camera-Z 深度，两档板端显示 48×32 径向测量及孤立缺测估计值。
- 摄像头原视频与深度图共用一个 RV1103 dToF＋2304×1296 H.265 采集会话。


不包含机械手模型、关节控制、手势、人手跟随、手套、其他深度模型包，也不提供独立原生 dToF/光子计数模块。主窗口由成像方案自动选择 dToF 模式，无手动调参入口。调参源码保留供工程专项验证。深度菜单、设备管理、渲染、语言、浮动/停靠、布局恢复和布局预设均保留。

当前默认标定、成像档位和自动导入见 [默认标定与原生 ToF 模式](docs/DEFAULT_CALIBRATION_NATIVE_TOF.md)。此前模型移除记录见 [仅保留上位机辅助推理](docs/HOST_ASSIST_ONLY.md)。v1.1.8 内测安装包的构建方式见 [模型保护与安装包约定](docs/MODEL_PROTECTION.md)。历史多后端安装版及实测见 [v1.1.7 安装与发布记录](docs/INSTALLER_1_1_7.md)。

深度图提供普通深度图保存、色标范围和原生档位输入角度。上位机辅助推理可同时保存配对的相机图像。

## 运行

双击根目录 **`START_RELEASE.cmd`**。已在本项目内配齐 Qt 6.11.1 MSVC x64 运行库；主机 FP16 推理另需兼容 NVIDIA GPU/驱动。普通启动在磁触觉模块首次可见后尝试一次默认串口：优先使用上次成功的端口、波特率、设备地址和模块，没有记录时使用首个可用端口、921600、地址 1 和 F 模块。收到首份 CRC 正确且量程有效的数据后，短暂等待稳定并以连续有效帧均值自动设置一次显示 delta 零点，完成后继续显示测量数据，不显示自动置零完成提示、帧数或耗时。正常通信时从首份有效测量起约 0.5～0.9 秒完成；置零期间临时按 10 ms 请求后间隔采样，随后立即恢复用户设置，因此 100 ms 甚至 60000 ms 的常规间隔也不会拉长置零等待。等待期间保留模型，暂不显示力箭头及曲线；到 0.9 秒仍未得到稳定均值时，自动用本次连接的最新有效帧设置一次 delta 零点，不显示完成提示，也不提示手动置零。“连接设置”每次启动默认展开，“显示设置”默认收起；之后仅由用户通过设置按钮或卡片内的最小化按钮显隐。连接成功、置零、连接失败、断开、热插拔重连和模块启停均不改变两个面板的显隐，展开状态不跨启动恢复。默认请求后间隔及下限为 10 ms，采集中可直接调整；该间隔从上次请求完成后计时，另加串口传输和设备响应耗时，界面按独立的约 30 Hz 刷新。轻微读数抑制默认开启，已有显示偏好继续保留。未连接设备、数据失效或切换到未连接型号时，保留模型并显示“设备未连接/数据不可用”，列表显示“--”，不会生成模拟读数。

磁触觉自动、手动和热插拔连接均先读取实际型号，再将采集及界面切到对应的指尖 F、末端 G 或超薄 S 模块。同一波特率下，当前地址读取失败时尝试厂家公共地址 0，并读取实际 ID、复核型号后继续采集。公共地址恢复用于单传感器总线。识别失败时提示用户检查波特率或从站 ID；用户可手动打开“连接设置”修改并重新连接，成功时自动纠正所选型号。每次连接使用当前波特率。

上位机启动后及 USB 插入时检测 RV1103；只有 ADB 身份及对应的 USB 网卡均在线时才继续判断，未连接或网卡尚未出现时静默等待。已保存设备的完整板端文件与当前配套资源匹配时，不弹提示，自动选中该设备并按当前选择启动共享成像；检查范围与 USB 一键连接相同。未保存设备或存在文件更新时，询问是否前往设置自动添加／更新，确认后打开设备管理并自动执行 USB 一键连接。取消后同一次 USB 插接不重复提示。深度图和摄像头原视频的「开始」「停止」「立即重连」控制同一个采集会话。用户停止后，同一次连接保持停止，检查期间点击停止也会撤销待执行的自动启动。离线专项和 `RV_TEST_OFFLINE_ONLY=1` 跳过默认串口、设备检测和自动成像，不开启硬件。delta 置零仅改变本次会话的显示基线，不写入传感器或修改原始读数。

### RV1103 USB 首次连接

首次启动的设备列表为空。启动时已插入及运行中插入的未登记 RV1103 均提示「是否前往设置自动完成新设备添加」，确认后自动打开设备管理并执行 USB 一键连接，可自动等待固件启动地址稳定，并为缺少受管地址的设备配置 USB 网络。使用 USB 数据线，板端需启用 ADB 和 RNDIS，并具备兼容的 Luckfox RV1103、SC3336 相机与 SPI ToF 硬件/BSP，或已部署兼容深度服务和 GEO2 标定。不要求预装指定 V1.2.0 算法交付包或匹配其旧驱动摘要。Windows 需识别两个 USB 功能。将 Android SDK Platform-Tools 的 `adb.exe` 及随附 DLL 放在主程序旁的 `platform-tools/`；直接运行 EXE 时也可使用 PATH 中的 ADB。

USB 流程自动读取序列号和 SSH 公钥，统一导入 2026-11-09 报告标定，无需用户选择标定。新设备使用原始相机 0° 标定输入、主机推理输入 0°；已有主机推理方向继续保留，显示旋转独立。上位机复用兼容地址，或为板端 `usb0` 补充 `172.32.0.93/16` 并设置开机恢复，保留其他地址；Windows 端仅配置对应的 USB 网卡为 `172.32.0.100/16`，可能出现系统管理员权限提示。新设备使用预置的 `root` / `luckfox`，已有设备优先复用 Windows 保存的凭据，缺少凭据时自动使用工厂 root 登录，不弹密码框；非工厂登录且没有已保存凭据或认证失败时明确报错，不绕过身份验证。SSH 公钥、序列号和标定验证通过后，密码保存至 Windows 凭据管理器，设备加入设备管理、设为当前默认设备并按当前成像模式启动。取消后，可保持 USB 连接，在「设置 → 设备管理」点击「USB 一键连接」重新自动处理。

首次连接未部署深度服务的新板时，上位机核对板端身份、固件依赖、采集占用和既有安装状态。自动部署配套 SPI 驱动、原生采集服务、高清视频配置、报告对应的 F6 标定、会话切换脚本及设备检查工具。已有其他版本的普通 ToF 驱动文件按 SHA-256 备份后替换；没有旧算法包也可直接部署。首次设置会接管原厂相机启动并保留启动脚本备份，继续使用板载相机程序及固件运行库。SPI 节点缺失时，仅对已识别的 Luckfox 配置工具应用已验证的临时 SPI0 配置。身份、标定、上传摘要、原生能力校验继续保留，异常安装目录、未释放的采集或故障状态需先处理。板端校验通过后登记设备并按当前成像方案启动。一键连接或板端文件安装失败时，弹窗会显示诊断报告路径并提供「打开所在文件夹」，便于用户将报告交给运维。

「USB 一键连接」同时适用于已经登记的设备。每次手动点击都核对完整板端运行文件；缺失、损坏或版本不匹配时，自动导入整套配套文件并在板端验证摘要、Native16 能力。自动检测复用同一完整文件清单，仅检查文件，不写板端；发现更新时先征得同意再跳转设置自动修复，USB 网络尚未配置时也先提示。旧运行目录移出活动路径并保留为回滚备份，替换失败恢复原文件。全部匹配时跳过文件写入，直接选中已登记设备并按当前方案连接，不再重复添加或提示到设备管理核对。设备别名、主机推理方向及可读取的长期传感器参数继续保留，标定统一迁移至当前默认方案。确认后的自动设置绑定当时的 USB 身份和启动会话，换板或重启后拒绝沿用旧确认；身份冲突、活动采集所有权和故障锁仍须先处理。

磁触觉“显示方式”按实际输出点数选择：指尖/末端触觉为 20、65、136 点，超薄触觉为 16、49、100 点。首次启动默认选择 136 点档（切换超薄触觉时为 100 点）和流畅渲染，后续恢复用户选择。模型、曲线和列表使用同一档点数；列表可选择任意输出点查看曲线。新增点沿用现有表面插值，原始采集与历史仍保留 20/16 个测点。三维数据约每 33 ms 更新，列表和曲线各自合并更新，置零、点选和显示设置即时刷新。模型上的固定 P 编号不再显示，点位、箭头和相机操作保持原有方式。

列表仅显示零点差值，表头为 X、Y、Z；未设置有效零点或数据不可用时显示“--”。delta 仍由当前值减去原始零点基线计算。硬件“抑制轻微读数”只作用于模型、曲线和列表的 X、Y 分量，绝对值不超过设置阈值时归零；关闭后恢复完整差值。Z 分量始终正常显示，不受抑制开关和噪声阈值影响。

“显示通信状态”每次启动时关闭，关闭时不占用布局空间。打开后可查看串口、设备地址、接收计数和错误信息，有过滤错误原因时才显示对应提示。重置视角和正面视角位于设置 delta 零点右侧。模拟数据生成、场景选择和底部模拟控件已移除；串口采集通过连接设置中的“断开”停止。

开始、采集中切换和可恢复的重连均由共享成像会话选择对应预设。空闲时选择方案会在下次开始时应用。

| 成像方案 | dToF 会话参数 | 相机 |
|---|---|---|
| 上位机辅助推理 | mode24，48×32 普通，单目标、Signal 和 Noise 关 | H.265 |
| 板端推理 | mode24，48×32 普通，单目标、Signal 和 Noise 关 | H.265 |
| 板端推理高精度 | mode25，48×32 高精度，单目标、Signal 和 Noise 关 | H.265 |

SPI 时钟、SNR、积分参数和周期沿用板端保存值，不改长期参数；软件标定统一使用当前 F6 方案。主机推理按软件时间戳匹配无告警 ToF，配对总预算 200 ms，包含 35 ms 时钟裕量。

设备管理显示只读的“2026-11-09 标定 / F=6（自动）”，不再提供 F1/F2 下拉或临时 FOV 选项。每次采集自动应用默认软件射线表，并验证相同 generation 的回执，保留实际传感器 FOV 和处理 FOV，不写传感器 EEPROM。当前参数与报告发布文件一并导入，标定应用和实际几何精度验证分开记录。

「USB 一键连接」和「安装板端采集支持」使用同一套按 SHA256 核对的板端文件计划，覆盖 F6 标定、内参、外参、SPI 驱动、采集程序、会话预设、工程调参和相机 ISP 配置脚本。更新在板端空闲时事务式执行，保留可读取的长期参数和回滚目录。板卡固件提供 SC3336 的 IQ 数据。

会话预设在停止或断电后失效。导入的采集脚本和程序保存在板端文件系统。当前 RV1103 的开机脚本只启动状态服务，等待上位机开始采集。其他镜像若在开机时自行启动深度服务，沿用该镜像原有的持久参数。上位机开始成像时会重新应用所选方案的预设。

## 独立配置

`config/` 保存本软件自己的设备档案和 INI 偏好。首次启动从随程序编译的 `config/first-run-settings.ini` 初始化磁触觉、深度图及原视频的可移植设置，后续使用本地保存的用户偏好。模板不包含 COM 口、设备地址、身份、标定或凭据。视频流地址由当前受信任设备档案生成。两软件后续各自保存；日常运行不会读写原软件的配置。本应用的窗口布局单独保存，不导入含机械手等模块的旧窗口布局。Windows 凭据仍由系统管理。

`UniDepthRuntimeRgb672VgaFP16RTX/` 是唯一主机推理运行包，含 RGB672→640×480 模型、DLL 和许可。旧模型及历史安装/测试资料按 SHA256 清单移入本次任务的外部归档。

## 开发

VS 2022 v143，Windows SDK 10.0.22621.0，Qt 6.11.1 MSVC x64，QtMsBuild。打开根目录同名 `.sln`，或运行：

```powershell
./tools/build_desktop.ps1 -Configuration Release -QtRoot E:/Qt/6.11.1/msvc2022_64
./tools/build_desktop.ps1 -Configuration Debug -QtRoot E:/Qt/6.11.1/msvc2022_64
```

构建默认同时重建配套的原生 RV worker 并更新其依赖 SHA256 清单，产物位于 `x64/<配置>/触想工作台.exe`。首次移植的一次性工具与文件指纹仅保存在 `x64/validation/port_import/`，不属于日常构建。

需要复现 CUDA 对照时，可为单独的开发构建显式传入 `/p:DctsUseCudaEp=true`。

离线专项统一使用 `tools/run_offline_tests.py`，涵盖 UI、触觉、调参、恢复及 USB 登记八组；脚本隔离配置和临时目录，缺报告、零断言或 FAIL 均判失败。`tools/verify_port.py` 用相同配对输入对比当前构建与参考 EXE，仅支持当前 640×480 模型，默认使用 RGB672 VGA RTX 包，按清单区分明文或加密加载。详细命令与有效代码行数口径见 [测试与源码统计](docs/TESTING.md)。
